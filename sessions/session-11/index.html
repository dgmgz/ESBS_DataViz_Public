S11-00 · Opening puzzle

Why can one “sales” number produce three different answers?

Imagine a Category view. We want to compare each category with customer lifetime sales and also show its contribution to the visible total.

Question AWhat did this row sell?

Calculate on each source row, then aggregate.

[Profit] / [Sales]
Question BWhat did this customer sell in total?

Choose customer grain even when Customer is not in the view.

{ FIXED [Customer Name] : SUM([Sales]) }
Question CWhat share of the visible total is this mark?

Calculate over the marks currently drawn.

SUM([Sales]) / TOTAL(SUM([Sales]))
Diagnostic habit

Before writing a formula, finish this sentence: “I need Tableau to calculate at the level of ___.”

Commit before continuing

A chart shows monthly sales. You need a cumulative line that changes when months are filtered out. Where should the calculation live?

S11-01 · Where calculations live

Four calculation levels, four different jobs.

1 · Source rowsRow-level calculation

Evaluated for every record before the view aggregates it.

[Profit] / [Sales]
2 · Query resultAggregate calculation

Evaluated after Tableau groups the rows at the view's level of detail.

SUM([Profit]) / SUM([Sales])
3 · Declared grainLOD expression

Calculates at a grain you define, which may differ from the view.

{ FIXED [Region] : SUM([Sales]) }
4 · Visible marksTable calculation

Runs after the view is built and depends on its layout and partitions.

RUNNING_SUM(SUM([Sales]))
Stable questionUse an LOD

“What is each customer's lifetime sales, regardless of the view?”

View-dependent questionUse a table calculation

“How do visible monthly sales accumulate from left to right?”

Worked example · why two profit ratios disagree

Ratio of totals is not the same as average of row ratios.

Order lineSalesProfitRow ratio
A€100€2020%
B€900€9010%
Average row ratio(20% + 10%) / 2 = 15%AVG([Profit] / [Sales])
Ratio of totals€110 / €1,000 = 11%SUM([Profit]) / SUM([Sales])

Interpretation: the first gives both order lines equal weight; the second weights them by sales. For overall profit margin, the ratio of totals is normally the meaningful answer.

S11-02 · Simplified order of operations

A filter only affects calculations that happen after it.

01Extract filters

Restrict the extract.

02Data source filters

Restrict the connected source.

03Context filters

Define the working subset.

04FIXED LODs

Calculate at declared grain.

05Dimension filters

Remove dimension members.

06Measure filters

Filter aggregated values.

07Table calculations

Operate on remaining marks.

Normal Category filterThe FIXED result stays stable

The FIXED expression was evaluated before the dimension filter.

Category added to contextThe FIXED result recalculates

The context filter now acts before the FIXED expression.

S11-03 · Level of Detail expressions

Declare the grain inside braces.

{ TYPE [Dimension 1], [Dimension 2] : AGG([Measure]) }
FIXEDIndependent of view detail

Uses only the dimensions declared in the expression. Best for reusable benchmarks and customer-, order- or region-level KPIs.

{ FIXED [Customer Name] : SUM([Sales]) }
INCLUDEAdd hidden detail

Adds a finer dimension to the view's grain, calculates, then aggregates the result back up.

{ INCLUDE [Sub-Category] : SUM([Sales]) }
EXCLUDERemove visible detail

Calculates at a coarser level by removing a dimension that is present in the view.

{ EXCLUDE [Sub-Category] : SUM([Profit]) }
If the metric should…ChooseExample
stay at a named grain when the view changesFIXEDCustomer lifetime sales
use more detail than the view displaysINCLUDEAverage sub-category sales by category
ignore one visible dimensionEXCLUDECategory profit repeated for each sub-category
Opening braceStart an LOD expression

Tableau now expects a scoping keyword, dimensions and an aggregate.

Scoping keywordFIXED · INCLUDE · EXCLUDE

Defines how the declared dimensions relate to the view.

Dimension declaration[Customer Name]

Names the grain to fix, add or remove.

Colon + aggregate: SUM([Sales])

States what measure Tableau calculates at that grain.

A normal Category dimension filter does not change the FIXED value. A context filter does, because it moves before FIXED in the order of operations.

Self-guided LOD ladder · complete in order

Each level adds one analytical decision.

Level 1 · reproduce

Regional Sales Benchmark

Question: what is total sales for the region each state belongs to?

Reveal calculation
{ FIXED [Region] : SUM([Sales]) }
Build checklist
  1. State → Rows.
  2. Sales → Columns.
  3. Region → Color.
  4. Regional Sales → Tooltip.
  5. Confirm states in one region repeat the same benchmark.
Level 2 · extend

State Contribution to Region

Question: what share of regional sales comes from each state?

Reveal calculation
SUM([Sales]) / MIN([Regional Sales])

Use an aggregation such as MIN because the LOD value is repeated at state rows and Tableau cannot mix aggregate and non-aggregate terms.

Validation

Format as percentage. Within each region, state contributions should add to approximately 100%, allowing for display rounding.

Level 3 · diagnose

Why did the benchmark change?

Add Category as a normal filter, then add it to context. Record the regional benchmark before filtering, after normal filtering and after context filtering.

Explain the result

The normal dimension filter acts after FIXED; the context filter acts before it. Context changes the data subset available to the LOD.

S11-05 · Table calculations

Table calculations work on the marks already in the visualisation.

Change the layout, sort order, filters or partition and the result may change. That is not a bug; it is the defining behaviour.

AccumulateRunning totalRUNNING_SUM(SUM([Sales]))

How much have we accumulated up to this mark?

ContributePercent of totalSUM([Sales]) / TOTAL(SUM([Sales]))

What share of the partition does this mark represent?

CompareDifferenceSUM([Sales]) - LOOKUP(SUM([Sales]), -1)

How far is this mark from the previous mark?

SmoothMoving averageWINDOW_AVG(SUM([Sales]), -2, 0)

What is the average of this mark and the previous two?

PositionRankRANK(SUM([Sales]))

Where does this mark sit inside its partition?

NavigateIndexINDEX()

What is the current mark's position in the partition?

Function mental models

LOOKUP(expr, -1)Bring back the previous mark

Useful for difference and percentage change.

WINDOW_AVG(expr, -2, 0)Average a three-mark window

Previous two marks plus the current mark.

INDEX()Number the current position

Useful for first/last mark logic and display control.

RANK(expr)Rank within the partition

The partition determines where ranking restarts.

Two rules

Tableau reads in a direction, and the calculation restarts for every partition. If the answer looks wrong, inspect Compute Using before rewriting the formula.

S11-07 · Table-calculation lab

Use a compact set of views to answer four different questions.

Task 4 · accumulate

Running sales

Build monthly Sales as a line. Duplicate the measure, apply Running Total and compute using Month.

Step-by-step
  1. Order Date → Columns; choose continuous Month.
  2. Sales → Rows.
  3. Duplicate Sales on Rows.
  4. On the second pill choose Quick Table Calculation → Running Total.
  5. Edit Table Calculation and address Month.
Business interpretation

The final mark equals the total for the partition; every earlier mark shows how much had accumulated by that month.

Validation test

Manually add the first three monthly values. The third running-total mark must equal their sum.

Task 5 · compare

Month-over-month difference

- LOOKUP(SUM([Sales]), -1)
Step-by-step
  1. Keep Month on Columns and Sales on Rows.
  2. Create the calculation.
  3. Address Month.
  4. Add the value to Tooltip or a second axis.
  5. Find the largest positive and negative changes.

Explain why the first month is NULL: it has no previous addressed mark.

At the fourth mark, the window contains marks 2, 3 and 4. Offset 0 is current; -1 and -2 are the two previous marks.

Task 7 · rank

Categories within each region

RANK(SUM([Sales]))
Step-by-step
  1. Region and Category → Rows.
  2. Sales → Columns.
  3. Create the rank calculation.
  4. Use Specific Dimensions: address Category.
  5. Confirm rank restarts inside every Region.
Debugging clue

If one global rank runs from 1 to 12, Region is being addressed or included in the same partition. Reconfigure Specific Dimensions.

S11-08 · Decision check

Choose the calculation from the behaviour the answer needs.

1Does the metric use each source row?

Use a row-level calculation.

2Does it use the view's current grain?

Use an aggregate calculation.

3Must it use a different or stable grain?

Use FIXED, INCLUDE or EXCLUDE.

4Must it respond to visible marks and layout?

Use a table calculation and configure Compute Using.
